# TypeShift: OpenSpec Constitution

## 1. Core Technology Stack
*   **Backend:** Java 21, Spring Boot 3.x.
*   **Concurrency:** Java Virtual Threads (`spring.threads.virtual.enabled=true`).
*   **Persistence:** SQLite (via Spring Data JPA / Hibernate) for the MVP.
*   **Frontend (Shell):** Thymeleaf and HTMX for server-side rendering, routing, and state management.
*   **Frontend (Typing Engine):** Vanilla TypeScript/JavaScript for zero-overhead, sub-16ms keystroke event handling.
*   **Build Tool:** Maven (or Gradle), enforcing strict lifecycle quality gates.

## 2. Architectural Boundaries
*   **Immutability:** Use Java 21 Records strictly for all Data Transfer Objects (DTOs), API requests/responses, and telemetry payloads.
*   **Stateless Telemetry:** The backend must expose REST endpoints to accept stateless telemetry payloads (keystrokes, accuracy, session duration) POSTed from the Vanilla JS typing engine.
*   **View Layer:** Thymeleaf handles all dashboard, authentication, and stage-selection views. Do not introduce heavy SPA frameworks (React, Angular, Vue) to the stack.
*   **Asset Management:** Typing practice materials (Hungarian and Vietnamese emails, orders) are stored as static JSON/Markdown files in the `src/main/resources` or an external local volume, served to the frontend via `@Cacheable` endpoints.

## 3. Static Analysis & Quality Gates
All code generated by AI must adhere to the following quality enforcement pipeline. The build must be configured to fail if any of these gates are breached:
*   **PMD:** Enforce rules for clean code, dead code removal, and optimal variable scoping.
*   **SpotBugs:** Catch concurrency issues, null pointer risks, and logical flaws.
*   **Checkstyle:** Maintain strict formatting alignment (e.g., Google Java Style or a defined custom XML ruleset).
*   **Security:** Integrate Semgrep rules to prevent SQL injection, XSS in Thymeleaf templates, and insecure endpoint exposure.

## 4. Frontend Implementation Rules
*   **Typing Engine Performance:** The typing interface must bind directly to `keydown` and `input` events using Vanilla TS. Do not use HTMX for per-keystroke network calls; HTMX is reserved for stage transitions, form submissions, and UI state updates outside the typing session.
*   **Scoring Logic:** Calculate "Tickets Cleared" (Speed), "Ledger Accuracy" (Error Rate), and the "Patience Meter" locally in the browser to prevent network latency from affecting the user experience, only syncing final metrics to the backend.

## 5. Domain Constraints
*   **Target Audience:** Adult learners preparing for retail and store management (cashier, boltvezető).
*   **Language Support:** Ensure UTF-8 encoding across all layers to correctly handle Hungarian (á, é, ő, ű) and Vietnamese (ă, đ, ơ, ư) diacritics.
*   **Gamification Nomenclature:** Use professional KPIs (Shift Evaluations, Error Rates, Orders Processed) rather than child-centric terms (badges, points, levels).
